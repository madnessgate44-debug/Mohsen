## Repo-by-repo implementation map

### Execution and orchestration

- **Firstborn** — [V] Active Forge implementation in `src/agent/forge.ts`, `src/agent/policy.ts`, `src/services/test-runner.ts`, and `.github/workflows/forge.yml`. It has exact-anchor patching, protected-path checks, a restricted test-command registry, bounded model calls, and evidence reports. The real cross-repository run was blocked at preflight because the workflow had no usable cross-repository token. The same-repository replica required an empty-plan recovery path because the keyless model returned valid JSON with zero changes.
- **Mohsen** — [V] Now hosts the Firstborn source snapshot, preserves its previous app under `legacy-mohsen/`, and exposes a ChatGPT-triggered same-repository Forge entrypoint through `.github/workflows/replicate-firstborn.yml`. Original source workflow copies are preserved under `replica-source/.github/workflows/`; this is a compatibility substitution, not a bitwise Git fork. The empty-plan/context-pollution fix is merged in PR #4. Actual Forge-created branch and commit were independently read back; PR #6 was opened by the connected GitHub integration because Actions PR creation is disabled.
- **Mission-runner** — [V] `.github/workflows/brain.yml` is the active “GitHub Arm” workflow triggered by pushes to `.missions/inbox/*.json`. `scripts/mission.js` validates JSON shape, rejects path traversal, uses `execFileSync` without a shell, and allowlists validation commands. It then commits and pushes directly to the requested target branch. The target owner/repository and target branch are not constrained to an explicit account allowlist, and protected paths are not separately denied. A second `github/workflows/brain.yml` exists outside GitHub's active `.github/workflows/` path and is not itself an active workflow.
- **Foryra** — [V] Browser-first PWA/operating-system prototype with mission-oriented files and an Engineering Execution OS. It has no conventional root package/build manifest in the inspected tree; automated behavior coverage was not established in this pass.
- **brain** — [V] Python service with API, tests, persistence/configuration, and a deterministic Markdown-brief worker. Its README explicitly distinguishes the implemented worker from model-backed research, browser actions, and repository editing; those broader capabilities must not be inferred from the Brain X project.
- **brain-chat-log (Brain X)** — [V] Node/TypeScript API with SQLite, participant API-key hashing, authenticated mission/conversation/artifact routes, and a GitHub dispatch route that attempts live issue creation when a token is configured, otherwise returning an inspectable handoff payload. However, the GitHub status/job routes appear unauthenticated and require correction.

## Account-wide architecture conclusions

1. The account contains at least three distinct execution models: **Forge** (model-generated plans/patches with evidence), **Mission-runner/GitHub Arm** (deterministic JSON patch missions with direct pushes), and **Brain X** (API-driven missions with live GitHub dispatch or a handoff payload). Their security and verification guarantees are not interchangeable.
2. Several repositories are prototypes, archives, or scaffolds rather than independently deployable products. A README or metadata capability claim is not proof of a working path.
3. Multiple public APIs rely on server-side Gemini keys without visible authentication/rate limits. Before public production use, add authorization, per-client rate limiting, request-size limits appropriate to the route, audit logging, and abuse controls.
4. High-stakes fallback responses must not invent facts or present random/heuristic values as measured results. This applies especially to Mohamy's legal responses and Gahiz's speech diagnostics.
5. Public uploads and state/chat artifacts require a data-classification pass. No transcript contents or credential values are reproduced in this report.

## Remaining coverage gaps

- **[B] Cross-repository writes:** both `FORGE_CROSS_REPO_TOKEN` and the tested `FORGE_DELIVER_TOKEN` fallback were unavailable to the Firstborn workflow. A user-configured credential with target-repository push access is required to enable Forge writes across repositories.
- **[B] Automatic PR creation in Mohsen:** repository policy blocks GitHub Actions from creating pull requests. Current workaround: Forge pushes a branch; ChatGPT verifies it and opens the PR through the connected GitHub integration.
- **[U] Full private-repository audit:** `G`, `brain-e2e-probe`, and remaining private-source coverage are not fully audited by the automated Forge workflow.
- **[U] Live deployment state:** code-level exposure risks are verified; actual production domains, access controls, and hosting configurations were not exhaustively verified for every application.
- **[U] Full-file/model audit:** this is a source-grounded cross-repository pass, not the output of a completed full-coverage model sweep for every file in every repository. Each repository still needs a file inventory, commit SHA, build/test result, and requirement-to-evidence ledger before it can be marked complete.
